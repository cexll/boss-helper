## Project Identity

Boss直聘助手: 减少投递简历的麻烦、提高投递简历的效率. A browser extension automating job search and application flows on zhipin.com for job seekers.

- **Primary users**: individual job seekers on desktop Chrome/Edge/Firefox; the extension runs inside the user's own logged-in zhipin.com session.
- **Business goal**: batch delivery of applications with filters, template/AI greetings, chat assistance, statistics — at human-plausible pacing (ban-risk trade-off is the product's core tension).
- **Lifecycle**: maintained public product, store-released.

## Core Invariants

- All zhipin actions run in the user's own session; no credential is ever persisted, logged, or shipped outside browser storage.
- Pacing/delay/limit rules in `useApplying` exist because zhipin punishes automation (黑号): changing them requires the ban-risk review (Critical Paths).
- A 配置 object written by an older version must remain loadable by a newer one: `formData` changes ship storage migration or backward-default handling in `conf`, never breakage.
- 打招呼 content the user configured is sent verbatim after 招呼语变量 rendering; silent fallback to the boss default greeting is prohibited when 自定义招呼语 is enabled.
- One 流水线 step outcome is one of: done / skip / abort (`abortPolicy`); a new handler must choose explicitly.
- `chat.proto` is the wire authority: encode/decode paths change with it, never drifted by hand.

## Forbidden Logic & Irreversible Operations

| Rule                                                                                        | Scope        | Why                               |
| ------------------------------------------------------------------------------------------- | ------------ | --------------------------------- |
| Never auto-reply boss chats as the user without explicit user-enabled AI 回复               | chat context | 黑号 risk, consent                |
| Never delete user storage/config data in a migration without an archive-and-restore path    | conf/storage | irreversibility on user data      |
| Never bypass the README risk framing to add stealth (fingerprint spoofing, captcha solving) | whole repo   | account safety > automation gains |
| Never persist cookies/tokens to files or fixtures                                           | all          | credential leakage                |
