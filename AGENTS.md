## Code Canonicality

One logic, one implementation. Versions evolve in git history, never in filenames or identifiers.

- Before adding a function/module/file, search for the existing implementation; extend it or justify the new one in the PR.
- Forbidden suffixes: `_v1/_v2/_new/_old/_backup/_temp/_copy/_final/_real/_improved/_refactored/_fixed/_legacy/_deprecated`. Near-miss debt (`Jobcard.vue` file vs `JobCard.vue` imports): unify, never extend.
- Refactor in place; no parallel old/new files "just in case" — git is the safety net.
- Commented-out code is debt: delete it (pre-existing blocks in `handles.ts`/`content.ts` are in Notes — don't grow the habit). Dead exports: wire or delete (knip ratchets). No scratchpad dirs in commits.
- Baselines move down only: `.baseline/findings.json` ceilings may not rise; a diff adding a violation removes one elsewhere.

## Conventions

- Files: TS camelCase, Vue PascalCase, tests `*.test.ts` beside the module. `FIXME` blocks release unless reviewers accept; markers name their reason.
- Deviations (non-default config, exclusions, ceilings) carry an inline comment naming the failure mode they prevent.
- Commits: Conventional Commits, leading gitmoji allowed (`✨ feat(chat): …`); agent commits add `Co-authored-by:`. PRs use the template. Branches `<author>/<slug>`, rebase before opening, `--force-with-lease` only; never delete a base branch with open stacked PRs.
- Coverage: **85% lines per .ts file** for added-or-changed vs the base; absent from lcov = 0% (fail closed). Zero-coverage legacy frozen in `baseline.legacy_untested_files` — shrink only; new files never join. `.vue` scripts uninstrumented (blind spot, review-owned).
- Breaking surfaces (search each when a change could reach it): wire (`chat.proto`, `src/message/`), persisted config (`conf/`, `types/formData.ts`), defaults (`conf/info.ts`), identity (`wxt.config.ts`, human gate). A break ships its migration in the same PR or a staged-coexistence contract with owner + deletion trigger.

- Root cause fixed; tests seen red before green; narrowest scoped verification ran (`check:all` only for repo-wide or CI diagnosis).
- No canonicality violations, no drive-by refactors; PR says what was NOT tested. Reviewing: substantiated blockers first, omit what gates enforce. Receiving: verify each claim, fix or rebut against the code.

## Architecture Discipline

TDD required — the test is the specification: Red → Green → Refactor → Commit; skipping red "because it's small" is where undetected damage lands. Test boundaries, error paths, transitions; "no exception thrown" alone is incomplete. Never mock the system under test — only its dependencies. Test files mirror sources; `abortPolicy.test.ts` is the pattern. Flaky = bug: quarantine with issue + deadline, fix/delete in 14 days.

## Agent Operating Rules

**May**: commit to feature branches (conventional, co-authored), open PRs to `main`, run local checks, propose this file's changes (human merge). **May not**: push `main`; force-push shared branches; `--no-verify`; weaken/skip/delete tests or gates for green; hand-edit `.output/`, `components.d.ts`, `auto-imports.d.ts` (regenerate); publish to stores or touch the `key`; read/print `.env*`, `local/`, `*.pem` or paste cookies/tokens anywhere; unreviewed dependency changes; modify CI without a PR flag.

- **Design friction — stop and ask** when the spec forces an awkward signature, contradicts a `CONTEXT.md` invariant, or duplicates an owned abstraction: name the tension, propose the simpler design, wait.
- **Evidence**: fresh command output this session (command + exit + key lines); verify the world, not the self-report. UI claims: screenshot + zero new console errors. PRs carry `## Runtime evidence` ("None — review-only" needs a reason).
- **Scoped verification**: narrowest check per surface — module tests; coverage+crap for changed .ts; `build:smoke` for build path. Scope via `bun run change-scope <base-ref>`, never guessed. CI owns exhaustive runs.
- **Loops**: 3 fix-recheck cycles max per failing check, then report tried commands + first actionable error; checkpoint-commit at green; one task = one branch.
- **Tiers**: local = full; stores/releases = nothing (human tag/manual dispatch).
- **Concurrency**: one worktree per agent; lockfile conflicts: `bun install` on the merged manifest, commit the result. An agent owns its PR to a terminal state; a human merges.
- **Incident ratchet**: a >30-min lesson becomes a dated Note; the third same-class incident becomes a lint rule or hook.
